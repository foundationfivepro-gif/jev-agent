# Unified local JEV STDIO server — implementation, not activation

The server exposes exactly `jev_recommend_host_route`, `jev_gate_command`, and
`jev_select_context`. It does not dispatch workers, install hooks, register an
MCP connection, load `.env`, discover credentials, or initialize a budget ledger.
The existing Claude server and defaults are unchanged.

## Concrete operator entry point

The JSON adapter is now implemented: see [LOCAL_OPERATOR.md](LOCAL_OPERATOR.md).
Use `scripts/unified_mcp_server.py --config /absolute/private/operator.json`.
It supplies all callbacks below from validated, expiring operator inputs; custom
Python is optional. Direct local host injection and cloud proxy placeholders are
separate transport modes. Neither has been activated by this release.

## Advanced Python launch contract

With dependencies already installed, use:

```text
/absolute/venv/bin/python /absolute/checkout/scripts/unified_mcp_server.py --binding /absolute/private/operator_binding.py
```

The operator binding is trusted Python code, not a tool argument. Review its
ownership, directory permissions, imports and contents before registration. It
must export `build_operator()` returning `unified_mcp.UnifiedOperator`. Do not
accept an operator binding uploaded or selected by an untrusted task author.

The binding supplies these existing-runtime dependencies:

| Field | Required evidence/behavior |
|---|---|
| `ledger` | `open_existing_ledger(absolute_path, approval, minimum_charged_usd=verified_prior_total)`; existing canonical database only |
| `transport` | `protected_transport(existing_verified_provider)`; provider returns the issued placeholder and enforcing HTTPS proxy, never a raw key |
| `runtime_id`, `session_id`, `discover` | Actual host identities and a fresh CapabilitySnapshot with observed supported controls/model IDs |
| `authorize_task` | Independently approve the exact routing TaskEnvelope, public data/destination, deadline and budget; default deny |
| `quote_route` | Complete, current RoutingAuthorization for the minimized routing payload |
| `authorize_operation` | For tool name and exact argument dict, return OperationGrant with stable operation ID, canonical argument hash, full operation ceiling and short expiry |
| `quote_decision` | For tool name, arguments and each minimized wire payload, independently verify a complete RoutingAuthorization including all fees and resolved identities |
| `workspace_roots` | Tuple of approved absolute Path objects; only these exact roots may be scanned |

`OperationGrant.arguments_sha256` is `payload_fingerprint(arguments)`. The gate
arguments are `command,cwd`; context arguments are `goal,root,globs,budget_tokens`,
including defaults. Expiry must be current and within five minutes. Operation
IDs must remain stable across retry/restart; never issue a new ID to bypass a
pending reservation. Changed content under the same operation ID fails closed.
No approval fields are inferred from tool text or generated by the model.

`open_existing_ledger` takes the already authorized Approval and the verified
prior spending floor. Use the true canonical approval ID/cap, not a new
allowance. Do not clone a cloud-owned ledger for concurrent Mac spending. Cloud
ownership and its live ledger have not changed in this patch. No handoff is planned. The concrete adapter also supports a distinct separately
approved local synthetic-smoke ledger capped at $0.10, with explicit new-file
initialization only. That separate approval is still pending; see LOCAL_OPERATOR.md.

The concrete JSON adapter supports the verified Mac host interface: an already
authorized injector supplies JEV_OPENROUTER_TOKEN to the STDIO child process.
No authenticated Mac 1Password account or working live credential has yet been
verified. Proxy placeholders remain a separate cloud mode; see LOCAL_OPERATOR.md.
Do not inspect keys with agent tooling, paste them into configuration, or copy
cloud placeholders to a machine without their enforcing proxy.

## Budget and file behavior

Routing reuses BoundHostRouting/OpenRouterSelector. Gate/context reserve the
entire approved operation ceiling in the same PilotLedger before any paid call.
Every batch and refinement requires its own exact-payload quote within the
remaining reservation. Known charges are summed; unknown charges retain the
whole reservation and halt the ledger. There are no retries or alternate
providers. Valid unexpired replay returns the recorded result without spending.
A failed context refinement is an error, not a silent usable result.

The transport fixes HTTPS `/api/v1/systemone`, model `jev-latest`,
uses the explicitly selected direct or protected-proxy mode and refuses redirects. All decision calls
validate provider, resolved model, usage, cost, choice shape and expiry.

Gate returns policy/advice and never runs a command. Deterministic hard blocks
remain intact. This server does not import a separate home-directory command
allowlist. Context selection reads only bounded files under exact approved roots
using the existing no-symlink descriptor boundary, with an 8 MiB aggregate file
limit per invocation; source text remains local.
Only privacy-screened goal, relative paths and parser symbols (plus synthetic
canaries) go to the model. Source snippets are not enabled. The server stores
screened result metadata and billed receipts in the ledger, not request/source
text. It suppresses legacy filesystem traces; no global monkeypatching is used.

## Proposed registration, after action-time approval

Merge a reviewed entry into the actual local app configuration without replacing
existing entries. These are placeholders, not verified Mac paths:

```toml
[mcp_servers.jev]
command = "/absolute/venv/bin/python"
args = ["/absolute/checkout/scripts/unified_mcp_server.py", "--binding", "/absolute/private/operator_binding.py"]
enabled_tools = ["jev_recommend_host_route", "jev_gate_command", "jev_select_context"]
startup_timeout_sec = 20
tool_timeout_sec = 120
```

A single context invocation can make several model calls, so the operation grant
must cover its total cost and deadline. Match the client timeout to that grant;
client cancellation does not prove the upstream request was free.

No configuration has been applied. Exact Mac paths, protected provider access,
current host catalog/controls, operator consent/quotes and ledger ownership must
be verified before activation. The clean existing Mac checkout may remain
untouched; launch from the separately reviewed work snapshot.

## Acceptance and limits

Offline tests use temporary ledgers and fake HTTP I/O with real protocol/schema
libraries. Verify a fresh local MCP initialize/tools-list exchange first, then
an explicitly approved public synthetic call for each tool with billed receipts.
The latter has not been performed and requires separate action-time approval.

After local verification, independently inspect the actual dot task tool list
and its connection. Local registration/skill discovery does not establish dot
propagation. This server cannot change the fixed parent model, intercept hidden
calls, enforce universal automatic routing, or dispatch native dot workers.
A recommendation still requires separate parent execution permission and budget.
